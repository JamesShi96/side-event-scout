# Side Event Scout（通用版）

# Side Event Scout

把「人工找 Side Events + 人工整理表格」自动化。输入大会名称，尽量全面发现并核实场外活动，默认按固定 8 列模板新建飞书电子表格，按日期排序。用户当次指定的交付方式或新模板优先。

## 固定模板与交付

- 本用户的最终格式基准是 [Z Potentials ICML 示例表](https://my.feishu.cn/wiki/OWWdwceRjihZXtk6HemctHPrnuc?from=from_copylink)。读取模板并按 本文后附“飞书固定模板” 继承品牌区、配色、列宽与八列表头；字段语义见 本文后附“读者表格格式”。
- 默认直接交付飞书电子表格链接。用户已经指定飞书时，不再询问 CSV / Markdown / 飞书三选一。本地结构化数据和核验记录是工作材料；只有明确要求其他格式或飞书暂不可用时才另交文件，并说明在线交付状态。
- 每个新大会新建一张表；模板作为只读参考。更新已有活动表须先读取现状，保留用户手工内容。

## 读者表格的写法

- **备注只写影响参加的条件**：优先保留「邀请制」「需审核」，其次是确有必要的名额、报名截止、票价和人群限制。例如 `邀请制、需审核、名额有限`。没有需要补充的条件就留空；不写研究过程、推荐理由、主观评价或其他字段已有的信息。
- **地址直接给结果**：知道就写明确地址；报名后显示的写 `Register to View Address；<城市>`；只知道场地就写场地和城市，仅知活动城市就只写城市。完全没有地点信息写 `TBA`。不写「未查到具体地址」「不能据此推断」「建议报名后确认」等解释。
- **Intro 直接用活动页描述原文**，保留原语言，不自行概括、翻译或补写；找不到就留空，不填 `/` 或「暂无简介」。遵守适用引用限制，不能全文复制时用原文短摘录并在表格外说明，不以自写摘要替代。
- **主办方优先查找 Organization，写公司或机构常用名**。有机构名称就不附个人姓名、页面联系人或职务；只有确实没有机构、由个人主办时才写个人。例外仅限对目标读者有广泛辨识度且确为主办者的知名人物，不能把知名嘉宾当主办方。保留有意义的联合主办、冠名赞助关系，不凭个人任职公司推定公司主办。
- 使用简短、陈述式措辞，不向读者提问或商量。确定的语气不等于编造确定性：不把信息缺失写成「无需审核」「免费」「开放报名」，不凭场地线索猜地址。需要查证的冲突保留在核验记录；必要时在表内用 `待确认` / `TBA` 简短标示。
- 用户修订表中的列顺序、留空方式和品牌标题可以沿用；残留长备注、截断文字和多余括号不作为新规范。用户明确说明的要求优先于表格残留写法。

**核心边界（最重要的一条规则）：只收大会「场外」的非官方周边活动，不收大会官方日程内的活动。** 要的是阿里云晚宴、MiniMax 线下交流会这类白天逛完正式展会后、偏休闲和 connect 属性的活动；不要大会官方的 keynote、tutorial、官方 workshop、官方展区活动。

## 工作流

用户仅要求清洗现有表格时，直接应用字段与输出规范；无需重新搜索，也不声称执行过搜索。以下发现流程和搜索覆盖说明仅适用于实际开展活动搜集的任务。

### Step 0 — 理解大会

用 web search 确认大会的：正式名称与常用缩写（含中英文）、举办日期、举办城市与主会场、核心人群（researchers / founders / investors / 开发者…）。

初始搜索时间窗 = 大会日期前 3 天到后 1 天。明确关联大会但在窗口外的活动单列核实，不机械丢弃；不同城市、卫星场及往年活动分别识别。

日期和时间统一为活动所在地时区，保留原始时区证据。浏览器顶栏的本地时钟不等于活动时区；日期卡片、页面正文、聚合页不一致时以主办方最新发布为依据。报名截止日期不能作为活动日期。

### Step 1 — 多路搜索

以 **Luma、小红书、活动聚合网站／社区清单** 为三条重点发现渠道，再用 Google 等搜索引擎及其他平台查漏。来源优先级用于分配检索精力，不替代事实核验；最终以主办方和原始活动页的最新信息为准。

1. **Luma**：搜索本届大会日历、非官方社区日历、城市发现页和独立活动页，兼顾 luma.com / lu.ma。大会中英文名、年份、城市与 dinner / mixer / reception / afterparty / happy hour / coffee / lunch / meetup 等词组合查询。打开日历全部可见日期分组，继续滚动或分页；静态抓取为空时使用当前环境可用的真实浏览器。日历显示“Coming Soon / 即将推出”就记录未上线，转查独立页面，不能宣称日历已全面覆盖。沿主办方及联合主办方查找同届其他活动。
2. **小红书**：优先做站内搜索，组合大会名称、缩写、年份、城市和晚宴／酒会／交流会／场外活动／招聘等关键词，结合综合与最新排序。读取相关笔记正文、海报和有价值的补充信息，再追到报名页或主办方原文。站内未登录时请求用户完成登录，同时推进其他渠道；不能绕过验证码、登录或访问限制。搜索引擎的 site:xiaohongshu.com / site:rednote.com 结果和公开转载只能补充，不能冒充完成站内搜索。记录实际完成的覆盖与访问缺口。
3. **聚合清单**：搜索本届 side-event calendar / event map / unofficial events / reception list / 社区汇总／飞书表格。活动聚合站、社区日历、媒体或公众号盘点、主办方系列活动页都可提供线索；不要凭网站声称“完整”就停止。读取全部可访问条目并回查原始活动页；与 Luma 和小红书结果交叉补漏。历史页面下线时才考虑网页存档，不以旧版日期填本届。
4. **搜索引擎查漏**：用 Google 等可用搜索引擎覆盖大会名与活动类型、主办机构、场地关键词。中文补晚宴／学术之夜／人才交流／私享会，英文补 founders / researchers / investors / drinks / networking。用户点名 Google 时实际检索或明确说明所用替代引擎。
5. **定向主办方**：从本届参展／赞助和已发现活动的机构名单继续挖。学术会议兼查研究机构、大厂、量化基金、VC 和本地 AI 社区；机构官网、微信公众号、LinkedIn、X、Eventbrite、Partiful、活动行等都需按线索补查。联办一场的机构可能另有多场，按日期区分。

先收集线索，再逐个打开活动原页核验；搜索摘要不能直接当成确认信息。日期、地点或大会关联仍未核实的列为待确认。候选较多时按来源或页面批次交给独立子 agent，返回结构化数据与证据，统一复核和去重。先用约 5—10 条真实候选验证字段与格式，再扩大处理。

**覆盖记录与停止条件**：记录每轮查询、访问来源、新增数量、失败渠道及待确认线索。没有固定活动数量上限；主要渠道已覆盖（或具体访问障碍已记录）后，连续 2 轮不同的补漏查询没有发现新活动，才结束本轮检索。这只表示截至抓取日的公开信息覆盖，不声称全部活动已发布，也不自动创建定时监控。

### Step 2 — 筛选

**收录**（场外周边，供参会人群 connect / 休闲）：
- Private Dinner / 晚宴、Mixer / Party / Reception / Happy Hour
- Coffee Chat / Café takeover / Coworking space
- 闭门交流、Salon、Demo Night、社群 Meetup、招聘晚宴（大厂 talent night 也算，人群匹配即可）

**排除**：
- 大会官方日程内的活动（官方 workshop / tutorial / keynote / 官方 expo booth 活动）
- 与大会无关的同城活动：活动页没提大会、也看不出面向大会人群的，不收
- 纯线上活动、纯广告 webinar

判断标准：活动页明确提到大会（@ICML、before WAIC 等），或时间地点+人群明显是冲着大会参会者来的。拿不准的保留为待确认线索，不冒充已确认活动；与已确认活动分组或简短标示 `待确认`，详细理由放核验记录，不塞进备注。

### Step 3 — 提取字段 + 去重

每个活动按 本文后附“读者表格格式” 的默认 8 列填写，各字段采用该文件规定的留空或占位方式，不统一填 `/`。不要编造。活动页本身缺日期/时间时，可用日历聚合页或盘点文章里标注的该活动日期回填，不能以大会日期代替活动日期；来源及冲突处理记入内部核验记录。逐项检查报名页上的邀请制和审核要求，不因用户样表中某一行备注为空就推定该活动无需审核。

去重规则：
- 主键：标题归一化（去 emoji / 标点 / 大小写）+ 日期；同名同日 = 同一活动
- 同主办方 + 同日 + 同时段 + 同地点，即使标题不同也疑似重复（同一活动多平台发布），合并成一条
- 合并时保留信息最全的一条，报名链接可多个并列，所有来源保存在核验记录；分析版的 Source 可并列标注
- 注意反例：同一主办方的**系列活动**（如同一公司连办三晚 dinner、同一日历下的多场 café 活动）不是重复，按不同日期/场次分行列出
- ⚠️ 不要用来源 URL 当去重主键：一篇媒体盘点文章会覆盖多个活动（同 URL ≠ 同活动）；只有活动平台链接（Luma/Partiful/Eventbrite）的同 slug 才能判定同一活动

### Step 4 — 可选推荐等级 S / A / B / C

仅在用户要求评级或分析版时执行；默认读者表不追加类型、Source、推荐等级、推荐原因。来源 URL、核验日期及冲突说明保留在独立核验记录中。

综合四个维度打分，推荐原因一句话点明关键维度：

| 维度 | 看什么 |
|------|--------|
| 主办方质量 | 一线 lab / 知名基金 / 明星公司 / 有影响力社群 > 无名主办方 |
| 人群匹配 | 面向 founders / researchers / investors 等目标人群的精准活动 > 泛人群 |
| 规模与深度 | 小规模 / 邀请制 / curated 名单（深度 networking）> 大规模开放（易参加但泛） |
| 信息可信度 | 信息完整、报名通道明确 > 信息残缺、真假难辨 |

- **S**：主办方一线 + 人群高度匹配 + 小规模/邀请制，networking 价值极高
- **A**：主办方质量好、人群匹配，规模中等或开放报名
- **B**：大规模开放活动，容易参加但人群较泛，深度 networking 价值一般
- **C**：相关性弱 / 信息不全 / 纯宣传性质，但仍可能有价值，留给读者自判

### Step 5 — 飞书交付与验收

1. 将已核验活动整理为同一份结构化数据。主表保持模板的 8 列；未知字段按格式规范留空或标示，待确认线索单列，不混入确认数量。保存来源 URL、抓取日期、时间与报名条件证据、冲突处理和排除理由。
2. 使用 lark-sheets skill 及其前置 lark-shared，先确认读取模板和建表所需身份与能力。参照当前 CLI 帮助选择建表和样式接口，不把过期命令固定写死。默认新建 “[Z Potentials] <大会缩写> <年份> Reception”，继承固定模板的版式；日期显示方式保持模板要求，底层类型按当前工具规范处理。
3. 新表顶部保留适用的品牌信息和可复用图片。旧大会海报、已过期二维码、历史置顶活动、隐藏行和旧日期合并不能不经检查直接复制；用本届数据重新建立日期分组。只有明确指定的活动才置顶或高亮。
4. 按日期升序、同日开始时间排序。主办方优先机构，地址简短明确，备注仅参加条件，Intro 保留原语言的原文或合规短摘录；摘录方式在表外统一说明。表外简短标明时区、更新日期及覆盖缺口，不增加研究过程列。
5. 写入后真实回读：核对全部活动条数、8 列映射、首尾记录、日期排序、时区、链接、样式与图片对象。接口返回成功不等于交付验证通过。只有在线表格已创建并读回确认后，才声称飞书交付完成。
6. 返回飞书链接、确认活动数和待确认线索数，以及必要的覆盖说明。仅用户要求分析版时追加评级。飞书受阻时保留可恢复数据、说明具体障碍，继续不依赖该障碍的工作。

## 注意

- **抓取时机决定查全率**：Side Event 信息半衰期极短——大会结束后 Luma 下沉过期活动、聚合站下线列表、微信传播链冷却。大会前 1-2 周到会中是黄金窗口；赛后回溯查全率必然大幅下降（需重度依赖 Wayback 多时间戳快照），必须在报告里向用户说明这一点
- 中国大会（WAIC 等）的周边活动大量只在微信公众号 / 小红书发布，Luma 覆盖不到，报告里必须提醒这一局限
- 活动信息随时会变（改期、改场地、报名截止），表格里记录的是抓取时点的信息；抓取日期放表格外的简短说明中
- 不要把同一大会往年的活动混进来，必须核实为本届及目标城市；窗口外关联活动另列


# Side Event List 读者表格格式

默认采用用户指定的 本文后附飞书固定模板，保持 8 列。表格直接告知读者活动信息，使用简洁陈述，不承载检索过程、推荐分析或与用户商量的措辞。

## 布局与排序

- 顶部品牌区、配色和列宽按飞书模板继承；标题行沿用用户提供的标题。本用户默认 `<大会缩写>线下活动总览-ZP整理`；其他用户不自动添加 ZP 品牌。
- 下一行表头，随后一行一个活动；用户模板已有顶部空行时可以保留，无需主动增加。
- 日期升序，同日按已知开始时间排列；日期未知的线索置后。待确认活动与已确认活动分组或简短标示，不冒充已确认信息。
- 时区、信息更新日期及搜索覆盖说明放表格外，不在每行重复。

## 默认 8 列

| # | 列名 | 填写规范 |
|---|------|----------|
| 1 | 日期/Date | `2026.9.28`。多日活动写起始日，跨度写时间列；未知写 `/`。 |
| 2 | 标题/Name | 保留活动页原始标题和原语言，可保留 emoji；不追加长篇核验解释或推荐评价。 |
| 3 | 主办单位/Org | 优先查找 Organization，写公司或机构常用名；有机构就不再附个人姓名或职务。只有确实没有机构、由个人主办时才写人名；广为目标读者熟知且确为主办者的知名人物可例外保留。多家用逗号或顿号分隔，必要时以 `；联合单位：…`、`；冠名赞助：…` 区分关系。未知留空。 |
| 4 | 📅时间/Time | `19:00 - 22:00`；跨天写 `9.28 18:00 - 9.29 01:00`；未知写 `TBA`，不追加「具体起止未公布」等解释。 |
| 5 | 📍地点/Location | 有地址：`场地名；街道门牌；城市`，保留可导航的具体信息，不重复城市。地址报名后可见：`Register to View Address；城市`。仅知场地：`场地名；城市`。仅知活动城市：只写城市。完全未知：`TBA`。 |
| 6 | 简介/Intro | 直接复制活动页的描述原文，保留原语言，不改写、概括、翻译或自行补充。找不到描述就留空。受引用限制时用原文短摘录并在交付说明中注明；不把摘录声称为完整描述。 |
| 7 | 报名/相关链接 | 优先直达报名页，必要的多个链接用 `；` 或换行分隔。无公开链接但明确有其他获取方式时写该方式；否则留空。 |
| 8 | 备注 | 仅保留直接影响参加的条件，优先邀请制、审核，其次必要的名额、截止、票价、资格限制。例：`邀请制、需审核、名额有限`。没有需要补充的条件就留空。 |

## 主办方：机构优先，个人兜底

- 先查活动页的 Organization、Hosted by、主办方简介及相关机构页面，识别实际主办公司、实验室或社群，不直接把平台展示的个人账户名单搬进表格。
- 确认有机构主办后，只写机构名。例如 `Bedrock Robotics；Anjelica Sarkar、Joshua Manela、Marta Stattmiller` 简化为 `Bedrock Robotics`。
- 只有未能确认任何主办机构且确为个人主办时，才写个人姓名；不靠个人履历或邮箱域名把其雇主认定为主办方。
- 知名人物例外须同时满足「目标读者普遍认识」和「确为主办者」；仅有高级职务不构成例外，演讲嘉宾也不因此列入主办方。拿不准知名度时，有机构就只写机构。

## 备注：短语即可

- 必须逐项读取并保留已确认的 `邀请制`、`需审核`；两者可同时存在。`RSVP` 只说明报名，不自动等于审核或邀请制。
- 有明确依据才写 `免费`、`无需审核`、`仅限博士生`、`限 30 人` 等；没有说明不等于没有限制。
- 不重复地点列的「地址报名后查看」，不复述 Intro 的活动内容，不写「偏产业工程与招聘交流」「值得关注」「建议自行确认」。
- 不把「未公布人数」「未查到票价」「搜索结果显示」「页面存在冲突」放进读者备注。这些信息如影响核验，存入独立记录；实质性日期冲突尚未解决时，将该活动列入待确认线索。
- 用 `、` 连接短条件，一般无需完整句子或句末句号；不为追求短而删掉真实参加门槛。

## 地址：结果明确、表达简短

- 不能根据「主会场附近」「某公司 HQ」推算街道门牌，也不能把合作大学或官方会场当成活动地址。
